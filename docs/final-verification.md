## Границы проверки

- На локальном сервере ключ GigaChat не задан (`configured: false`). Внешняя доступность, качество свежего распознавания настоящей моделью и её предварительной классификации в этом прогоне не подтверждались. Интеграционные ответы модели получены только от локальной фикстуры.
- Docker-движок не запущен. Контейнер целиком не собирался и не запускался. Совместимость печати с его версией Typst проверена отдельно; сетевые настройки, сертификаты и окружение production требуют проверки на сервере.
- XML-пример самого прототипа содержит только часть полей редактора. Экспорт воспроизводит этот набор и повторяет товарный узел для каждого товара. Валидация по полной XSD внешней таможенной системы не выполнялась.
- Тип входного документа определяется по имени файла; сканы без текстового слоя и бинарный DOC не поддерживаются текущим извлечением.
- Не заполненные по документам стоимость, платежи, ставки и курсы остаются для уточнения; неподтверждённые сведения не рассчитываются по предположению.

## Исправление сборки и проверка контейнера

После указанного прогона получен лог серверной Docker-сборки: проверка TypeScript не находила `Bun` и `bun:test`, а также отклоняла `Uint8Array<ArrayBufferLike>` как `BlobPart`. Предыдущая команда `nuxt typecheck` не охватывала эти проверочные скрипты в локальном окружении.

Исправлено:

- `@types/bun` версии `1.3.14` явно добавлен в devDependencies и `bun.lock`.
- Новый `tsconfig.checks.json` включает скрипты и тесты с типами Node/Bun. `bun run typecheck` проверяет и приложение, и этот набор файлов.
- Тестовый загрузчик создаёт собственный `Uint8Array` для Blob; ожидаемые статусы параметризованного теста сохраняют литеральные типы.
- Docker build stage использует Node 22 для Nuxt CLI и Bun 1.3.14 для установки. Это устраняет наблюдавшееся незавершение Nuxt под Bun. Проверка типов обязательна перед сборкой. Прежний обход, допускавший успех по таймауту при наличии выходного файла, удалён.

Проверка выполнена с нуля, без прежних `node_modules`, `.nuxt`, `.output` и локальных переменных окружения проекта. `bun install --frozen-lockfile`, расширенная проверка типов и 46 тестов прошли. Полный `docker build` по Dockerfile завершился кодом 0; `bun run typecheck && bun run build` внутри образа завершились самостоятельно, без таймаута. Проверен Linux/arm64 образ; серверная архитектура отдельно не эмулировалась.

Образ запущен на loopback-порту 3114. Подтверждены HTTP 200, 24 одинаковые выдачи демо, 13 строк, сохранённые рекомендации ТН ВЭД, HTTP 422 для повреждённого PDF и настоящий PDF-экспорт с Typst 0.14.0. Все пять страниц контейнерного PDF просмотрены; кириллица, товары и итоговые суммы присутствуют. После перезапуска контейнера версия и checksum демо остались прежними. Временный контейнер остановлен. Логи: `../audit/deploy-docker-build-node.log`, `deploy-container-smoke.log`, `deploy-container-restart.log`.

Таким образом, ограничение о непроверенном контейнере выше относится к предыдущему прогону и снято этой проверкой. Внешний GigaChat по-прежнему не вызывался. Чекпоинт до исправления: `codex/checkpoint-dt-13-before-deploy-fix`, после: `codex/checkpoint-dt-14-docker-build-fixed`.
